# 分段串流閘門：六項待裁定事項

**日期**：2026-08-05
**背景**：檢查點已裁定從「全部輸出完之後」改到「**每一段顯示之前**」——後端累積到一個段落邊界、跑完出口掃描才送出該段；命中就把該段連同禁詞丟回 AI 只改寫該段，改完再檢查才顯示。打字機即時感保留，代價是每段多 1–2 秒暫存（掃描本身只要 0.23 毫秒）。

本文列出這個決策**衍生**的六項待裁定事項。前三項是**規格落差**（原規格在分段模式下做不到原本承諾的事，必須改寫規格文字）；後三項是**實作參數**（可授權我方決定，僅需知會）。未裁定前，事項 10／12／16 無法定案開發。

---

## 甲、必須裁定（規格落差，非實作細節）

### 甲-1　完整性檢查無法逐段執行

**問題**　`b §8` 的三項檢查——段落標題是否齊全（`expected_sections`）、自由提問是否在 1,000 字內、社會期望反應 A 段是否含佐證措辭——**都必須看完整回答才能判定**，無法在單段層級執行。

**選項**

| | 做法 | 影響 |
|---|---|---|
| A（建議） | 逐段**增量累計**已出現的段落標題，全部輸出結束後才判定 | 判定時機不變，僅實作方式調整；無使用者可感差異 |
| B | 每段各自檢查「這段是不是某個期望段落」 | 會誤判：一個期望段落常橫跨多個顯示段 |

**我方建議**：A。

---

### 甲-2　完整性不過時，已顯示的段落收不回來

**問題**　`b §8` 原規定「不過 → 帶『缺了什麼』的具體原因**重生成一次**」。但分段模式下，判定「缺段落」時前面的段落使用者早已看到，**無法重生整篇替換**。

**選項**

| | 做法 | 影響 |
|---|---|---|
| A（建議） | 改為「**只生成缺少的段落並附加於後**」，不重生已顯示內容 | 使用者看到的是內容繼續長出來，體驗連貫；但段落順序可能與指令定義的順序不同 |
| B | 保留整篇重生，畫面清空重來 | 與本次決策「沒有畫面清空重來」的前提直接衝突 |
| C | 不補救，僅記錄後轉人工 | 使用者拿到的是不完整的回答 |

**我方建議**：A。**若採 A，`b §8` 的「重生成一次」需改寫為「補生成缺漏段落一次」。**

---

### 甲-3　`blocked` 的安全承諾必須改寫

**問題**　`b §7` 原文是「若最終仍有洩漏，**不得把該回覆回傳前端**（阻擋並落人工）」。分段模式下，若第 5 段怎麼改寫都清不乾淨，第 1–4 段**已經顯示**——能做到的只有「該段與其後不再顯示」，做不到「整份回覆使用者完全沒看到」。

**這不是實作缺陷，是分段方案的固有性質**：要達成原文承諾，就必須整篇緩衝（第一個字要等整篇生成完），與本次決策相斥。

**選項**

| | 做法 | 影響 |
|---|---|---|
| A（建議） | 接受此性質，把 `b §7` 與對外說法改寫為「**掃描未通過的段落不會顯示；已顯示的段落無法收回**」 | 承諾與實際行為一致 |
| B | 維持原承諾文字 | 對外承諾與系統實際能力不符 |

**我方建議**：A。**這一項最重要**——不能讓「有掛出口掃描器」被理解成「使用者絕對看不到任何內部標記」。實際上單段掃描通過才顯示，使用者確實不會看到洩漏內容；只是「整篇阻擋」這個保證退化為「逐段阻擋」。

## 乙、可授權我方決定（實作參數，知會即可）

### 乙-1　「段」怎麼切

掃描器是對整段文字跑正則，需要確定性的切段規則。

**我方預定**：以**空行**分段；另設 **400 字上限**，超過則在最近的句號處提前切。設上限是為了避免長段落把暫存時間從 1–2 秒拉到 5 秒以上。若貴方對「每段最長等多久」有明確期望，請告知，我方調整上限值即可。

### 乙-2　跨段邊界的洩漏

內部標記可能剛好被切在兩段之間（例如前段結尾是 `CIA_`、後段開頭是 `05`）。

**我方預定**：掃描每段時帶入前一段末尾少量字元的重疊窗一起比對。成本可忽略，不影響顯示內容。

### 乙-3　單段重寫失敗的上限

**我方預定**：單段重寫上限 **2 次**；超過則停止後續輸出、顯示轉人工訊息，並在稽核紀錄標記。設上限是為了避免 AI 持續產生同樣問題時陷入無限重寫。若貴方希望改為 3 次或其他值，請告知。

## 丙、連帶調整：稽核紀錄結構

原設計的 audit 物件（`_ LOG 實作補充說明 for victor.txt`）把洩漏重試記成單一數字：

```json
"retry_count": { "leakage": 0, "completeness": 0 }
```

分段模式下洩漏重試是**逐段發生**的，單一數字無法還原「哪一段出問題、改寫幾次」。我方將擴充為逐段紀錄（段序、命中詞、重寫次數、該段最終狀態），並保留原有欄位以維持相容。此項為我方內部實作，**不需貴方裁定**，僅一併說明。
