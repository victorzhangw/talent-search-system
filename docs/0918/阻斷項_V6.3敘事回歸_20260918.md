## 1. 一句話

`0915改特質 02_08 V6.3 spec_.xlsx` 把 08 分頁 **2389 列裡的 1053 列（44%）敘事換成了較舊、較短的版本**，平均長度從 181 字掉到 71 字，同時把規範明禁的絕對化措辭大量帶回來。`04_SPEC_0917_V7.xlsx` 原封不動沿用了這個狀態（V6.3→V7 只再動 42 列）。

**照原訂計畫匯入 V7，等於把這個回歸鎖進資料庫。**

## 2. 證據

### 2.1 規模

| 比對 | 清洗後不同的列數 |
|---|---|
| V6.2 → V6.3 | **1053 / 2389（44%）** |
| V6.3 → V7 | 42 |

1053 列裡有 **1007 列變短**，平均長度 **181 字 → 71 字**。

### 2.2 內容形態

| 版本 | `CIA_01_A × CIA_09_A` 的敘事 |
|---|---|
| V6.2 | 表現為「長線自持的推進者」。他對品質與進度的要求一貫，不需要外部催促也能持續把工作往前推；同時面對眼前輕鬆的誘惑，他多半能守住原本的節奏，不會為了一時舒服偏離原本計畫… |
| V6.3 / V7 | 長期目標的長跑者。具備極強的抗誘惑能力與延遲滿足感，能自主完成長期艱難任務。 |

V6.2 是行為導向、帶機率性措辭的寫法；V6.3 是構念式、帶絕對化措辭的舊寫法。

### 2.3 絕對化措辭（全域輸出規範乙-5 明禁）

| 詞 | V6.2 | V6.3 | V7 |
|---|---|---|---|
| 極強 | 4 | **56** | 56 |
| 極度 | 13 | **90** | 90 |
| 絕對 | 2 | **14** | 14 |

規範乙-5 寫的是「一律使用機率性措辭；禁止絕對化」。這些字現在住在**注入給模型的資料裡**，等於一邊叫模型別寫、一邊把範例餵給它。

### 2.4 校準機制連帶失效

#### 證據鏈

| # | 出處 | 內容 |
|---|---|---|
| 1 | `b_打包規則_v3_20260917.md` 第 90 行 | 「社會期望反應的校準由資料自帶，程式不需任何動作：全塊時四欄自帶完整指令；**索引時行為面向尾句自帶可信度句**；System 靜態規則見到標籤即全域生效。」 |
| 2 | 同檔第 13 行（§0 T3） | 校準特質＝固定三元素 `{CIA_33, ANI_23, SPA_12}` |
| 3 | `a_LOG完成版模板_v2_20260917.md` 第 77–78 行 | 索引行格式＝`- CIA_01_A｜盡責｜高度自律：（semantic_description 全文）`，並註明「社會期望反應的校準句由其 **K 欄**自帶」 |
| 4 | `services/trait_blocks.py::render_index_line()` | 實際渲染的是 `row.description` |

也就是說：b §4 講的「行為面向尾句」＝ 02 分頁 K 欄 `semantic_description` ＝索引行冒號後那一整段。這條鏈是逐檔查證的，不是推論。

#### 三個校準特質 band A 的 K 欄，逐版本比對

資料來源：三份 spec 的 02 分頁，以 `(trait_id, band)` 對位取第 10 欄。

| 版本 | ANI_23_A / CIA_33_A |
|---|---|
| V6.2 | …不利於己的部分較少主動揭露；**其自述內容的可信度需以行為事例佐證。** |
| V6.3 | 明顯傾向以社會期待方式作答，可能歪曲信念與答案以取得認可，導致評鑑可用性下降。 |
| V7 | 答題或表達時傾向以社會期待的方式呈現，可能修飾說法與答案以取得認可，資訊可信度需交叉驗證。 |

（SPA_12_A 在 V6.2 與另兩者相同；V6.3 已是「資訊可信度需交叉驗證」，V7 把三者統一。）

**「以行為事例佐證」這句從 V6.3 起就不在資料裡了**，而 b §8 的佐證檢查要的正是
`佐證／行為事例／工作樣本／不以單次` 這四個詞（`completeness_check.EVIDENCE_TERMS`）。

所以可以確定的是：**b §4 描述的那個機制，在 V6.3／V7 上已經不成立**，而 DB 現在就是 V6.3。

#### 更正：這不是 66% 失敗率的原因

> 本節初稿寫的是「這就是 `calibration_evidence` 失敗率 66% 的根因」。**那個因果宣稱是錯的，在此撤回。**

反證來自 payload 本身。掃 61 MB `prompts.log`，數當時實際注入的是哪一版 K 欄文字：

| 日期 | payload 含 V6.2 佐證句 | 含 V6.3 歪曲句 | 當天 calibration 通過/失敗 |
|---|---|---|---|
| 2026-03 ~ 07 | 0 | 有 | （該期間無此欄位） |
| 2026-08-10 | 3 | 0 | 3 / 0 |
| 2026-08-12 | 5 | 0 | 2 / 1 |
| 2026-08-16 | 3 | 0 | 1 / 1 |
| **2026-08-18** | **16** | 0 | **4 / 13** |
| **0831** | **25** | 0 | **2 / 9** |
| 2026-09-04 | 8 | 0 | 1 / 0 |
| 2026-09-07 | 5 | 0 | 0 / 2 |

失敗最集中的 08-18 與 0831，payload 裡**明明帶著**「其自述內容的可信度需以行為事例佐證」這句話，檢查照樣失敗 13 次與 9 次。**句子在的時候就已經失敗了**，所以它的消失解釋不了那 66%。

三件事因此要分開講：

1. **機制確實壞了**（可查證的事實）：V6.3／V7 的 K 欄不再帶那句話，b §4 的描述與資料不符。
2. **66% 的成因仍然不明**（撤回的宣稱）：失敗是在句子還在的時候量到的。真正的成因沒有定位，需要另外查。
3. **往前看的風險**（尚未量測）：把唯一一處會示範該用語的資料拿掉，只會讓模型更不容易寫出那四個詞，不會更容易。但這是推論——2026-09-01 之後 `calibration_evidence` 幾乎全是 `n/a`（名單裡很少有人社會期望反應落 A），**沒有 V6.3 生效後的任何一筆量測**。結案方法見實作文件附錄 D-2 的合成探針。

#### 附帶發現：V6.3 的文字是「回到八月以前」，不是新寫的

上表第一列值得單獨看：2026-03 ~ 07 的 payload 帶的是 **V6.3 的「歪曲／評鑑可用性下降」** 那句，八月才換成 V6.2 的佐證句。

換句話說，V6.3 不是把文字改成一個新版本，而是**換回了八月以前的舊文字**。這件事本身不構成結論，但它與 §4 的推測（0915 是在一份較舊的底稿上套用改字，而不是在 V6.2 上改）指向同一個方向。

## 3.6 決定性證據：02 分頁只改了 25 個儲存格

把 V6.2 → V6.3 的 02 分頁逐格比對（339 列 × 19 欄）：

| 欄位 | 改動筆數 | 改了誰 |
|---|---|---|
| `trait_name_en` | 6 | **ANI_02** 的 `Resilience1` → `Resilience`（三個 band 各兩處） |
| `semantic_description` | 6 | 只有 `CIA_33`／`ANI_23`／`SPA_12` |
| `management_focus` | 5 | 同上三個 |
| `ai_do` | 5 | 同上三個 |
| `ai_dont` | 3 | 同上三個 |

**合計 25 格，全部落在三個校準特質，外加一個 `name_en` 的錯字修正。** 中文名 0 筆、band 標籤 0 筆——檔名雖然叫「改特質」，但 113 個特質的名稱一個都沒改。

（`Resilience1` 那筆是有意義的修正：`name_en` 以數字結尾會讓 ANI 受測者的韌性特質解析不到，`verify_packer_data_health` 至今還留著那條回歸測試。）

**所以 0915 的意圖範圍小而明確：修一個 `name_en` 錯字、重寫三個校準特質的四欄文字。**

而同一份檔案的 08 分頁換掉了 **1053 列（44%）**。

**這個不對稱本身就是最強的證據**：如果 0915 是有意的內容改版，不會出現「02 分頁只動 3 個特質、08 分頁卻換掉四成」這種比例。02 分頁明顯是在 V6.2 上改的（只有 25 格不同），08 分頁卻是舊版——**同一個檔案裡兩個分頁來自不同的底稿**。

## 4. 最可能的成因（待客戶確認）

§3.6 之後，這已經不太像推測了：**02 分頁是在 V6.2 上改的（只有 25 格不同），08 分頁卻整片是舊版**。同一個檔案的兩個分頁來自不同底稿，最合理的解釋是 0915 的編輯是在一份較舊的工作簿上套用那 25 格改動，而不是在 V6.2 上改。

三項旁證指向同一個方向：

1. **02 分頁的意圖範圍極小**（3 個校準特質＋1 個 `name_en` 錯字），與 08 分頁 44% 的替換完全不成比例。
2. **客戶自己 0917 更新的 a／b 文件，內容正本欄位仍指 V6.2**（§3.5.1）——如果 V6.3/V7 的敘事是有意改版，這一欄應該跟著換。
3. **2026-03~07 的 payload 帶的就是 V6.3 那句校準文字**（§2.4 附帶發現）——V6.3 不是寫了新版本，是換回八月以前的舊文字。

但這仍然是推論。**必須由客戶確認哪一版是他們要的**，不能由實作方代為決定——這是內容正本的歸屬問題。
