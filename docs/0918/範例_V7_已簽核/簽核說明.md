### 關於受測者 ID 佔位符

原範例用的是 `RESP_R2`／`RESP_R3_DUAL`／`RESP_TEAM_01`／`RESP_TEAM_02` 這類示意代號，而系統實際輸出的是依名單順序指派的 `RESP_01`／`RESP_02`。

原本的驗收腳本為此開了一條容忍條款（「examples use ad-hoc placeholders」）。新範例直接用系統實際輸出的代號，**這條容忍條款就可以拿掉**，驗收反而更嚴格。

若貴方希望保留原本的示意代號，請告知，我們會改回。

## 4. 請貴方確認的事

**請實際讀過新範例的敘事內容，不要只看差異行數。**

原因要說明白：這四支驗收腳本原本的意義是「我方的程式輸出，與**貴方獨立產出**的範例逐字相同」。現在範例改由我方用同一套程式、同一個資料庫產生，那條斷言就退化成「我方的輸出等於我方的輸出」——只有在程式不具決定性時才會失敗。

獨立性從「獨立產出」變成「獨立審閱」。這比原本弱，但只要貴方確實讀過內容，仍然有效。

**若貴方有能力自行產出範例，我們優先採用貴方的版本**——那才保得住原本的獨立性。

具體要確認的是：新範例裡的交互敘事與特質欄位文字，就是貴方要的 V7 內容。
