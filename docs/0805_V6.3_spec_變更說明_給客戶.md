## 2. 為什麼 core / marginal 只是備註，不是開關

`question_injection_table_v9.json` 的 `risk_endpoints.adopted` 是 71 個 **2 元素**陣列 `[trait_id, band]`，**本來就沒有級別欄位**。級別只存在於人閱版定案表，是 2026-07-27「Core＋Marginal＋property_peak 兩端**全數採用**」那次裁決的**理由紀錄**。既然全採，三類在程式裡的行為完全相同——就是一個布林的集合成員判定。

因此 D 欄（`endpoint_level`）的價值是稽核與可回溯調整（日後若要退回「只採 core」，資料已備妥），**不是控制流程**。我方程式將固定以「**該列存在於 `09_endpoints` 即為端點**」判定，不讀取級別值。請確認此即貴方原意。

### 3.2 我方資料庫：既有三張表零變動，新增兩張端點表

先更正一個說法：本次**確實需要動我方資料庫**，只是動的方式是「新增」而不是「修改」。

- **既有三張表**（`trait_definitions`／`trait_bands`／`trait_interactions`）**完全不變**：無 `ALTER`、無改型別、無改主鍵外鍵、無重新命名、無 backfill 腳本，所有既有查詢不受影響。
- **新增兩張表**：`endpoint_blocks`（對應 `10_endpoint_blocks`）與 `trait_endpoints`（對應 `09_endpoints`），與 spec 的兩張新分頁一對一。

之所以不把端點塞進既有 `trait_bands` 的欄位，正是為了支撐第 5.2 節的擴充需求：欄位式做法每新增一個端點型別就要多一欄（等於每次都要改結構又改程式），而獨立表新增型別只是多幾列資料。另外風險端點是 (特質, band) 層級、作答校準是特質層級，兩種粒度也無法共用同一個欄位。

DDL 已備妥並在正式資料庫上以「執行後回滾」方式實測通過（74 列端點資料全數符合外鍵／值域／唯一性約束，四項違規測試皆被正確擋下）。此為我方內部工程項目，不影響貴方作業。

## 5. 日後的維護方式

### 5.1 新增／移除一個端點（同型別）

在 `09_endpoints` 加一列：填 `trait_id`、`band`、`endpoint_type=risk`、`endpoint_level`、`block_key=calib_risk`、`note`。存檔交付我方重跑匯入即可。移除則刪該列。

**不需要改程式碼、不需要改 JSON、不需要發版。**

### 5.2 新增一個**端點型別**（例如未來要加「情境壓力端點」）

這是本次結構調整的主要目的。分兩種情況：

**情況一：新型別併入現有子區塊**（例如也放進「作答校準與風險提示」）
→ 只需在 `09_endpoints` 加列，`endpoint_type` 填新代號、`block_key` 填 `calib_risk`。**程式零改動。**

**情況二：新型別要有自己的子區塊**
→ 除了 `09_endpoints` 加列，還需要在 `10_endpoint_blocks` 加一列，並由**貴方提供三項資訊**：

1. **子區塊標頭的逐字字串**（例如 `#### 交互作用——◯◯◯`）。我方不得自行命名——依 `00_外包交接說明.md` 的職責邊界，打包程式零語意判斷、不改動任何文字，區塊名稱是內容決策。
2. **`sort_order`**：這個新區塊排在現有三塊的哪個位置。
3. **`priority`**：見下節。

**程式仍然零改動**——因為區塊標頭、順序、優先序全部是資料。

### 5.3 一條交互同時觸及多個型別時怎麼辦（`priority` 欄的用途）

一條交互有**兩端**，兩端可能命中不同型別。這不是假設情境——用現行資料實測 08 分頁 2389 條可解析的交互列：

| 情況 | 條數 |
|---|---|
| **同時觸及 風險端點 與 校準特質** | **28** |
| 只觸及風險端點 | 870 |
| 只觸及校準特質 | 79 |
| 兩者皆不觸及 | 1412 |

例如 `CIA_05_C × CIA_33_A`：前者是風險端點，後者是校準特質。

今天這 28 條沒有問題，因為兩個型別共用同一個子區塊，放哪都一樣。**但只要未來出現「新型別要有自己的子區塊」，這 28 條（以及新型別帶來的類似情況）就必須有一個明確規則**：該交互要進哪一塊？會不會被輸出兩次？

`10_endpoint_blocks` 的 `priority` 欄就是為此保留。**此規則已於 2026-08-05 定案：一條交互只輸出一次，取其命中型別中 `priority` 數字最小的那個區塊。** 目前的值（related 1 ／ calib_risk 2 ／ other 3）即為現行行為的等價表述，套用新規則後輸出與現行完全相同。新增型別時請一併指定其 `priority`。
