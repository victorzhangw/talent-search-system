根本原因分析 — 安全缺口

  • 1
    /chat/ 端點無任何認證 任何人只要知道 API URL，即可不限次數直接呼叫 LLM。沒有 API Key、沒有 Session Token 驗證。
  • 2
    CORS 完全開放（CORS(app)，無 origins 限制） 任何網域的瀏覽器都可以對後端發出跨域請求，等同無 CORS 防護。
  • 3
    /auth/login 無密碼驗證 登入端點接受任意 email，不核對密碼即可取得 session token，無法有效識別合法用戶。
  • 4
    無 Rate Limiting 同一 IP 或用戶可在短時間內發出無數請求，無任何頻率保護。
  • 5
    無每日 Token 預算上限 LLM 費用完全無上限控制，費用異常時沒有任何自動熔斷機制。
  • 6
    無 IP 來源限制 系統僅應被特定伺服器（UAT/App 後端）呼叫，但實際上任何 IP 皆可存取。

各項修改詳情

T2
CORS 來源白名單
將 CORS(app) 改為僅允許環境變數 ALLOWED_ORIGINS 列出的網域。
本機開發用的 localhost:5300、localhost:5000、127.0.0.1:5300 自動加入例外，不受環境變數影響。
BackEnd/api_v2/app.py ALLOWED_ORIGINS=https://uat.traitty.com,https://app.traitty.com
T3
Rate Limiting（速率限制）
引入 flask-limiter 4.1.1，對 /chat/ 路由套用：每用戶 30 次/小時、150 次/天。
限速 Key 優先使用 user_id（請求 body），無則退回 IP。超限回傳 429。
新建 extensions.py 避免 app.py ↔ routes/chat.py 循環匯入。
BackEnd/api_v2/extensions.py（新建） BackEnd/api_v2/routes/chat.py BackEnd/api_v2/requirements.txt
T4
每日 Token 預算上限
在 chat() 函式開頭，查詢當日 ChatMessage.token_usage 累計值。
若超過 DAILY_TOKEN_LIMIT 立即回傳 429（QUOTA_EXCEEDED），不呼叫 LLM。
重置時間：UTC 00:00（每日自動歸零）。
BackEnd/api_v2/routes/chat.py BackEnd/api_v2/config/settings.py DAILY_TOKEN_LIMIT=50000
IP
IP 白名單中介層
before_request middleware 對 /chat/ 及 /api/v2/* 路徑執行 IP 驗證。
讀取 X-Forwarded-For 首個 IP（支援 Proxy 環境），不符合白名單回傳 403。
127.0.0.1、::1、localhost 永遠放行（本機開發例外）。
BackEnd/api_v2/app.py ALLOWED_IPS=3.169.55.15,54.192.248.91
LOG
LLM 呼叫記錄強化
conversations.log 每筆 [AI] 記錄新增四個欄位，方便事後稽核與計費分析：
CallerIP UseCase Latency (ms) Error (bool) BackEnd/api_v2/routes/chat.py
ERR
LLM 錯誤獨立 ERROR 記錄
當 LLM 呼叫失敗（has_llm_error = True）時，額外在 conversations.log 寫入 ERROR 級別的 [LLM ERROR] 條目，方便監控系統過濾告警，不需掃描全部 INFO 記錄。
BackEnd/api_v2/routes/chat.py
UX
前端錯誤訊息脫敏
_mock_stream_fallback() 不再將原始 API 錯誤字串（如 Error code: 402 - {'error': {'message': 'Insufficient Balance'...}}）串流至前端。
使用者改看乾淨的中文提示，原始錯誤僅記錄至後端 rag_service.log。
