## 三、D1 與程式碼現況的矛盾（重要）

三個「伺服器入口點」都以扁平匯入取得 app：

```python
# wsgi.py / run_waitress.py / run_uvicorn.py
from app import create_app
```

但 `app.py` 自 commit `838cbdb`（2026-01-20，"Fix: 修正 Chat API 回應與資料庫遷移問題"）起改用相對匯入
（`from .config.settings import Config`），因此以頂層模組載入 `app` 必定失敗：

```
$ python -c "import sys; sys.path.insert(0,'.'); from app import create_app"   # cwd=api_v2
FLAT IMPORT FAILED: ImportError attempted relative import with no known parent package
```

也就是說 `run_waitress.py`（最後修改 2026-01-16）與 `run_uvicorn.py`（2026-01-17）在那次 commit 之後就再也起不來；
`wsgi.py` 雖然 2026-03-09 還被動過，但它的 `from app import create_app` 與 `from utils.logger import ...`
兩行都還是扁平匯入，同樣無法載入。

唯一能運作的是 `asgi.py`（2026-07-12）——它把扁平匯入包在 try/except 裡，失敗後退到
`from BackEnd.api_v2.app import create_app`，前提是專案根目錄在 `sys.path` 上。

另外 repo 裡的兩份 web.config 都**沒有** `<handlers>` / wfastcgi 設定，內容都是把請求 rewrite 到
`http://127.0.0.1:5000` 的反向代理。

**推論：** 正式機跑的很可能不是 repo 目前這份程式碼的這幾個入口點（例如另有一份扁平部署的舊複本，
或正式機的 web.config 與 repo 不同）。U8 在 Q1 釐清前不得開始 Do。
