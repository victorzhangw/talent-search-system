# 11. 作答校準特質（CIA_33/ANI_23/SPA_12）零工序驗收測試

**類型**：驗收測試｜**優先度**：P2｜**依賴**：05（特質分流）、06（交互選列）、10（完整性檢查）

## 目標

不是新邏輯，而是一組**跨事項的整合驗收測試**，確認校準特質在「零工序」原則下，於三個既有機制中都被正確處理：特質分流（不升全塊）、交互選列（歸入正確子區塊）、回答後檢查（佐證措辭）。

## 為什麼獨立列一項而不是併入 05/06/10

因為「零工序」本身容易被誤解成「什麼都不用做」，導致漏實作；同時它橫跨三個不同模組，容易在單一模組的單元測試中被遺漏，只有整合測試才能真正驗證「三處都對」。`_ LOG 實作補充說明 for victor.txt` 第一節就是專門為此寫的澄清文件，值得對應獨立的驗收項目，而不是分散淹沒在其他事項的測試清單裡。

## 規則澄清（逐字引用 `_ LOG 實作補充說明 for victor.txt` 第 1–70 行）

> 「校準零工序」只代表：不新增獨立的 `[作答校準]` 文字區塊。不由程式自行撰寫校準說明。不修改資料正本中的敘事文字。
>
> 但程式仍須辨識固定的校準特質：`CIA_33`、`ANI_23`、`SPA_12`，並在以下三處使用：
> 1. 交互作用選列。
> 2. 交互作用子區塊分組。
> 3. LLM 回答後的佐證措辭檢查。
>
> 校準特質若沒有被題目匡列，不得因此升成完整特質區塊；它仍留在「其他特質索引」。

## 匡列型案例（逐字引用，用於構造測試資料）

假設：本題匡列集合 `S = {CIA_16, CIA_18}`；受測者另有 `CIA_33_A`；`CIA_33` 是校準特質但不在本題匡列集合。

組裝結果應為：
- `CIA_16`、`CIA_18`：進入「判讀主體特質」完整區塊。
- `CIA_33_A`：留在「其他特質索引」，**不升成完整區塊**。
- **不另外生成 `[作答校準]` 區塊**。

若正本存在下列交互：
- `CIA_16_A × CIA_33_A`：因為其中一端是本題匡列特質 `CIA_16`，歸入「交互作用——本題相關」。
- `CIA_33_A × CIA_11_B`：若兩端都不在本題匡列集合，但因為含校準特質而被選入，歸入「交互作用——作答校準與風險提示」。

## 回答後檢查案例

若受測者的校準特質為 A 段，回答中至少要出現一種佐證語意，例如：「建議搭配實際行為事例確認」「可再參考工作樣本或主管觀察」「不宜只根據單次自陳結果判斷」。若回答完全沒有這類語意，完整性檢查應回報：
```
含社會期望反應 A 段，但回答缺少佐證類措辭。
```
（此檢查邏輯已在事項 10 實作，此處是驗收，不是重新實作。）

## 完整驗收案例表（逐字引用）

| 測試情境 | 預期結果 |
|---|---|
| 校準特質未被匡列 | 留在索引區，不升完整區塊 |
| 校準特質被題目匡列 | 依一般匡列規則進入完整區塊 |
| 交互列只因校準特質被選入 | 歸入「作答校準與風險提示」 |
| 交互列同時包含匡列特質與校準特質 | 歸入「本題相關」 |
| 校準特質為 A 段，回答有佐證語意 | 通過 |
| 校準特質為 A 段，回答沒有佐證語意 | 重生一次；仍失敗則轉人工 |
| 輸出中出現獨立 `[作答校準]` meta 區塊 | **驗收失敗** |

最後一列特別重要：早期 v1.1 提案曾設想過獨立的 `[作答校準|…]` meta 塊，但定案時已簡化掉——若實作中出現任何形式的獨立校準區塊，即為不符規格，需要修正回事項 05/06。
