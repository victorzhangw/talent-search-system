# 05. 特質區塊分流邏輯（全塊區／索引區，b§2）

**類型**：核心邏輯｜**優先度**：P1｜**依賴**：01（特質正本）、03（受測者資料）

## 目標

依受測者已測特質與本題匡列集合，把特質分成「全塊區」（完整四欄注入）與「索引區」（一行摘要），並套用欄名正規化。

## 規則（逐字引用 `b_打包規則_v2_20260727.md` §2）

```
受測者特質集合 P = {(trait_id, band)}（僅其受測測驗）
匡列集合 S = 題庫表該題的匡列 ID（僅其受測測驗的欄位）；自由提問或全人型題 → S = P 的全部 ID
命中風險端點 R = { t | (t, band_of_t) ∈ 風險端點表 }

全塊區   ＝ S 中的特質：注入四欄原文（行為面向/管理重點/可用於/禁止）＋標頭 [特質 | ID_band | 標籤]
索引區   ＝ P - S：每特質一行「- ID_band｜中文名｜band標籤：行為面向全文」
```

> 注意：**風險特質與校準特質不因此升全塊**；未匡列時留在索引區（其行為面向已自帶所需語意）——這是最容易被誤實作的地方，`00_外包交接說明.md` 常見誤區第 2 條專門點名：「❌『風險／校準特質要升成全塊區』→ ✅ 不升；未匡列就留索引區」。

## 輸出格式（逐字引用，必須完全一致）

全塊區標頭＋內文（`a_LOG完成版模板_v2_20260727.md` §2.1）：
```
[特質 | CIA_22_A | 自在於無規則]
行為面向：…    管理重點：…    可用於：①…②…③…    禁止：①…②…③…
```
（實際渲染時四欄各自換行，見 `新版LOG範例_匡列型_壓力題_v7.txt` 第 57–61 行範例。）

索引行格式（`b_打包規則_v2_20260727.md` §2）：
```
- ID_band｜中文名｜band標籤：行為面向全文
```
範例（`新版LOG範例_匡列型_壓力題_v7.txt` 第 100 行）：
```
- CIA_01_A｜盡責｜高度自律：做事有一致的自我要求，能主動掌握進度、顧品質與收尾…
```

## ⚠ 資料欄位陷阱（2026-07-31 第二次複查實測）：`injection_set` 不是全塊區的來源，`scoped_traits` 才是

`question_injection_table_v9.json` 每題同時有兩個看起來都像「本題要注入哪些特質」的欄位，**名字取得最像的那個是錯的**：

| 欄位 | 實際意義 | 用在哪 |
|---|---|---|
| `scoped_traits` | 依測驗分組的**題意匡列集合**，＝本事項的 S | **全塊區（本事項）** |
| `injection_set` | 扁平清單，＝`scoped_traits` ∪ 校準特質 | **交互選列的過濾集合（事項 06）**，不是全塊區 |

實測 22 題全數驗證：`injection_set` 對每一題都**恰好等於** `scoped_traits` 扁平化後再聯集三個校準特質（`CIA_33`／`ANI_23`／`SPA_12`），19 題匡列型每題都是 `len(injection_set) == len(scoped_traits) + 3`，0 筆例外（3 題全人型兩者皆為空）。

資料檔自己的 `injection_note` 欄位也寫明了這件事：
> 交互過濾集合＝本清單 ∪ 受測者命中之風險端點特質（見 risk_endpoints.adopted）；**全塊注入僅限題意匡列（scoped_traits）**

**為什麼這是陷阱**：`injection_set` 這個名字直觀上像是「要注入的集合」，實作時很容易直接拿它當 S 用；但它已經把校準特質包進去了，一旦拿它當全塊區來源，**三個校準特質就會被錯誤升級成完整特質區塊**——這正好違反本事項與 `00_外包交接說明.md` 常見誤區第 2 條反覆強調的「校準／風險特質不因此升全塊」，也會直接讓事項 11 的驗收案例表最後一列（「輸出中出現獨立校準內容＝驗收失敗」）踩雷。

客戶參考骨架用的是正確的欄位（`question["scoped_traits"]`，第 136 行），實作時照抄骨架即可；但若你自行改寫或看到 `injection_set` 覺得更方便而改用它，就會中招。

## ⚠ 另一個容易誤做的動作：不得在 runtime 做構念家族擴張

`construct_families_v1.json` 交付給實作方**僅供稽核比對，程式不需載入**。`01_設計總說明與決策定案_v2_20260728.md` §3 明文：

> **構念家族補全**（⚠ **資料生成期機制，非打包層步驟**）：題目匡列某構念時，跨已測測驗補齊該家族。此補全**已在題庫表生成時做完**（22 題 scoped_traits 實測缺口 0），打包程式**不得**在 runtime 再做一次 S 擴張（會違反 00 的職責邊界；且家族表含 SDR 校準族，再擴張會把校準特質誤升全塊區，違反 b §2 註）。

實際打開 `construct_families_v1.json` 確認：家族表中**確實含有 SDR 校準族**（`ANI_23`／`CIA_33`／`SPA_12` 三者互為家族成員）。所以若在 runtime 對 S 做一次家族擴張，只要題目匡列了任一校準特質的家族成員，三個校準特質就會被一起拉進 S、進而升成全塊區——與上一節的 `injection_set` 陷阱殊途同歸，都是同一種錯誤結果。**兩個坑要一起避開。**

## 特別情境：全人型題

`question["type"] == "whole_person"` 或自由提問時，`S = P` 的全部 ID——此時**沒有索引區**（全部特質都進全塊），標頭字串要換成：
```
#### 判讀主體特質（全人型＝全部特質）
```
（一般匡列型用 `#### 判讀主體特質`）。
