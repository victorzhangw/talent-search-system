# 00. 外包交接說明 — Traitty LOG 打包程式

> 讀者：LOG 打包（匯出／組裝）程式的外包實作團隊。
> 一句話定位：**你把「內容正本＋題庫匡列」按規則組裝成送給 LLM 的 payload，並掛好出口檢查。你不生產、不改動、不判斷任何語意內容。**

---

## 〇、這支程式做什麼（輸入 → 輸出契約）

**把三類輸入，用確定性規則組裝成一份最終 LOG 檔。**

```
輸入 A 特質敘事文件   （0722 02_08 V6.2 spec_.xlsx：02 特質欄位＋08 交互敘事；已導出 traits_113_v6_2.json）
輸入 B 特質評鑑結果   （受測者姓名/ID/已測測驗/各特質分數→band；schema 見 b §1.1。實際來源＝Talent Chat API v2 GET /candidates/{id}/report，對接欄位見 03_API對接說明）
輸入 C 快速提問內文   （question_injection_table_v9.json＝c 題庫的機讀版：型別/匡列特質ID/清理後指令）
        │
     打包程式（本文＋b 規則）
        │
輸出   最終 LOG 檔：[SYSTEM PROMPT] ＋【輸入數據】組裝區 ＋ [任務指令]
        （目標格式＝兩份「新版LOG範例_*_v7.txt」）
```

> A 是「這些特質長怎樣」的內容庫（靜態）；B 是「這個人各特質落在哪」的評鑑結果（每人不同、每次請求帶入）；C 是「這次要回答哪一題、該匡哪些特質」的題庫。程式把 B 當索引，去 A 取內容、照 C 的匡列規則，組成 LOG。設計緣由見 `01_設計總說明`。

---

## 一、職責邊界（最重要，先讀）

**你負責（純機械組裝）**
- 讀入受測者資料（姓名／ID／已測測驗／各特質 band）與本次題目（或自由提問文字）。
- 依 `b_打包規則` 做：特質區塊分流（§2）、交互選列（§3）、組裝順序（§5）。
- 掛上 §6 單元檢查、§7 出口掃描、§8 輸出完整性檢查。
- 全程只有集合查找、去重、分組、字串拼接——**零語意邏輯**。

**你不負責、且禁止（語意住在資料表裡，不在你的程式裡）**
- 改動任何指令文字、特質欄位敘事、交互敘事。原樣複製，一字不改。
- 自行決定「匡列哪些特質」——匡列是題庫表給的**資料**，不是你算的邏輯。
- 做任何評分、歸類、可信度或風險的語意判斷。
- 對社會期望反應族另寫「校準」邏輯——校準由資料自帶＋System 靜態規則生效，程式零工序（見 b §4）。

**遇到語意疑義**：一律回問內容方（Traitty 團隊），不自行詮釋、不改資料。

## 二、端到端資料流

```
受測者資料 + 題目/自由提問
        │
        ├─ 特質分流(b§2)  →  全塊區 / 索引區
        ├─ 交互選列(b§3)  →  本題相關 / 校準風險 / 其他參考 子區塊
        └─ System 靜態文字(a 文件，原樣複製)
        │
      組裝(b§5)  →  完整 LOG payload
        │
      LLM 生成回答
        │
      出口掃描(b§7) + 輸出完整性(b§8)  →  殘留內部標記=0 才放行
        │
      輸出給前端
```

## 四、驗收 DoD（外包完成的判準，逐條可驗）

1. **重現範例**：用兩份範例（匡列型／全人型）的輸入，你的程式要能組出與範例一致的 `【輸入數據】` 區塊；其中 `[SYSTEM PROMPT]` 段須與 a 文件**一字不差**。
2. **單元檢查全過**：b §6 四項每次組裝都跑且通過（全塊數／索引行數對齊、交互兩端 ID 都在、字面符號乾淨、子區塊歸屬正確）。
   ⚠ 第 3 項的殘留代號檢查**只掃敘事本文、必須排除標頭**——標頭 ID 是合法且必須保留的（見 DoD 5）。
3. **完整性檢查掛上**：b §8 段落齊全（子集寬鬆判定）＋社會期望反應 A 段佐證措辭檢查，可運作。
4. **出口掃描掛上**：b §7 掛 `exit_scanner_wordlist`，per-request 動態縮小；**紅隊實測內部標記殘留＝0 才放行**。
5. **ID 保留**：每個特質標頭與交互標頭的 `XXX_nn` ID 必須保留在 payload 中（runtime LLM 靠 ID 消歧同名跨測驗特質，**不可剝除**）。

## 五、常見誤區（實作前務必看過）

- ❌「匡列特質我要自己算」→ ✅ 匡列來自題庫表欄位，是資料。只有**自由提問／全人型題**才用「該受測者全部受測特質」。
- ❌「風險／校準特質要升成全塊區」→ ✅ 不升；未匡列就留索引區，其行為面向已自帶所需語意（b §2 註）。
- ❌「交互選列要設上限截斷」→ ✅ 無題意截斷上限，過濾即預算；全人型的「補充 10 條／>90 防呆」是**結構參數**不是可調配額（b §3）。
- ❌「校準要另寫程式」→ ✅ 零工序，資料自帶＋System 靜態規則（b §4）。
- ❌「expected_sections 沒對齊就硬擋」→ ✅ 它是 best-effort 提示，§8 採**子集寬鬆判定**，未命中列警告非硬擋；**空陣列＝該題略過段落檢查但必須 log**（3 題如此）。段落來源**只能是 expected_sections**，不可自行解析指令文字。
- ❌「everyday 詞出現就攔」→ ✅ 只擋構念式用法（後接程度／高低判定才攔），單獨日常語用放行（b §9）。
  ⚠ 白名單鍵是**巢狀**的：`trait_names_blocklist.everyday_words`、`band_labels_blocklist.everyday_labels`。取頂層會得到空集合 → 日常詞全被誤攔。
- ❌「多人／單人請求可以直接組」→ ✅ 組裝前必查 `audience`，不符即**拒絕請求**；否則會把佔位字串「僅適用單人／僅適用多人」當任務指令送出（b §1.1）。
- ❌「四欄原文直接加欄名前綴」→ ✅ 部分正本儲存格已自帶「可用於：」「禁止：」，須「缺則補、有則不重複加」（b §2）。
- ❌「範例裡沒有回答樣本是漏交付」→ ✅ 本包定位是**規格／組裝包**；回答樣本屬「上線前複測」工作包，另附，不在此包。

## 六、升級路徑（不確定時回問誰）

- **語意／內容／匡列疑義**（某特質該不該匡、某敘事怎麼解讀）→ 回內容方（Traitty 團隊）。勿自行詮釋或改資料。
- **打包程序歧義**（某步驟怎麼實作）→ 先對照 `b_打包規則`；仍不明回內容方。
- **你發現資料表本身矛盾**（如兩檔對不上）→ 回報內容方，不要自行「修正」資料。
