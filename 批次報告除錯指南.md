## 🐛 常見問題診斷

### 問題 1: 前端沒有呼叫 API

**症狀**：
- Console 沒有顯示 "Batch Report Fetch Debug"
- Session Storage 是空的

**可能原因**：
1. `handleSelectionConfirmed` 沒有被呼叫
2. `fetchBatchTraitReports` 函數沒有被執行

**檢查**：
```javascript
// 在 handleSelectionConfirmed 開頭添加
console.log('[DEBUG] handleSelectionConfirmed called with ids:', ids)
```

**解決方案**：
- 確認點擊「開始提問」按鈕有觸發 `handleSelectionConfirmed`
- 檢查是否有 JavaScript 錯誤阻止執行

---

### 問題 2: 沒有 assessment IDs

**症狀**：
```
[ChatContainer] Extracted assessment IDs: []
[ChatContainer] No assessment IDs found for selected candidates
```

**可能原因**：
- 候選人資料中沒有 `latest_assessment.assessment_id`

**檢查**：
```javascript
// 在 Console 中執行
console.log(candidates.value)
// 檢查每個候選人的 latest_assessment 結構
```

**解決方案**：
- 確認 `/api/v2/candidates/` API 回傳的資料包含 `latest_assessment.assessment_id`
- 檢查候選人是否有完成評估

---

### 問題 3: API 呼叫失敗 (404)

**症狀**：
```
[ChatContainer] Response status: 404 Not Found
[ChatContainer] ❌ Failed to fetch batch reports
```

**可能原因**：
- 路由沒有正確註冊
- API URL 不正確

**檢查**：
```bash
# 測試 API 端點是否存在
curl -X POST http://localhost:5000/api/v2/reports/batch \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"assessment_ids": [62, 63]}'
```

**解決方案**：
1. 確認 `app.py` 有註冊 `reports.bp`
2. 重新啟動後端服務
3. 檢查 API URL 是否正確（應該是 `/api/v2/reports/batch`）

---

### 問題 4: API 呼叫失敗 (500)

**症狀**：
```
[ChatContainer] Response status: 500 Internal Server Error
[ChatContainer] Error response body: ...
```

**可能原因**：
- 後端程式碼錯誤
- 上游 API 呼叫失敗

**檢查後端日誌**：
```
[Batch Reports] ERROR fetching from service: ...
```

**解決方案**：
1. 檢查後端 Console 的完整錯誤訊息
2. 檢查上游 API token 是否有效
3. 檢查上游 API 是否正常運作

---

### 問題 5: 回傳空陣列

**症狀**：
```
[ChatContainer] Response data: { reports: [] }
[ChatContainer] Number of reports received: 0
```

**可能原因**：
- 上游 API 沒有回傳資料
- assessment_ids 不存在

**檢查後端日誌**：
```
[Batch Reports] Received 0 results from service
[Batch Reports] WARNING: No results returned from service
```

**解決方案**：
1. 確認 assessment_ids 是否正確
2. 檢查上游 API 回應
3. 確認候選人是否有完成評估

---

### 問題 6: 無法匹配 candidate_id

**症狀**：
```
[ChatContainer] Processing report for assessment_id: 62
[ChatContainer] No candidate found for assessment_id: 62
```

**可能原因**：
- `selectedCandidates` 中的 `latest_assessment.assessment_id` 與回傳的 `assessment_id` 不匹配
- 資料類型不一致（數字 vs 字串）

**檢查**：
```javascript
// 在 Console 中執行
console.log('Selected candidates:', selectedCandidates)
console.log('Response reports:', data.reports)

// 檢查 assessment_id 的類型
selectedCandidates.forEach(c => {
  console.log(`Candidate ${c.candidate_id}: assessment_id = ${c.latest_assessment?.assessment_id} (type: ${typeof c.latest_assessment?.assessment_id})`)
})
```

**解決方案**：
- 確保 assessment_id 的類型一致（都是數字或都是字串）
- 修改比對邏輯，使用 `==` 而非 `===`

## 🔧 快速測試腳本

### 測試 1: 直接測試批次報告 API

```bash
# 替換 YOUR_TOKEN 為實際的 token
curl -X POST http://localhost:5000/api/v2/reports/batch \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{
  "assessment_ids": [62, 63, 64, 61]
}' | jq
```

**預期回應**：
```json
{
  "reports": [
    {
      "assessment_id": 62,
      "traits": [
        { "name": "同理心", "score": 85, "band": "High" },
        ...
      ],
      "assessment_date": "2025-12-03T09:30:48.315395Z"
    },
    ...
  ]
}
```

### 測試 2: 檢查候選人資料

在前端 Console 中執行：

```javascript
// 檢查候選人資料結構
console.table(candidates.value.map(c => ({
  candidate_id: c.candidate_id,
  name: c.name,
  assessment_id: c.latest_assessment?.assessment_id
})))
```

### 測試 3: 手動觸發批次獲取

在前端 Console 中執行：

```javascript
// 手動呼叫批次獲取函數

  selectedCandidateIds.value.includes(c.candidate_id)
)

// 檢查 Session Storage

```
